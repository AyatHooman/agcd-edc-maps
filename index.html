AGCD — Fortran SI vs Python OI

Interactive comparison maps for 2025. Each run below opens a viewer where you pick the date; every map is a 6-panel comparison of the Fortran statistical interpolation and the Python optimal-interpolation engine. Top row — station maps: observed value, Fortran (obs − grid), Python (obs − grid). Bottom row — Fortran rainfall, Python rainfall, and their difference. Hover a gauge for its values (incl. its QC verdict); scroll to zoom (all panels zoom together).

Every gauge is shown, including the ones a QC step rejects. On the bottom row the station markers are coloured by QC status — ● PASS, ● SUSPICIOUS, ● REJECT, ● none / pseudo — and every hover popup reports the gauge's QC status and flags.

Monthly runs

Fortran QC disabled (operational)  |  Python QC disabled Same inputs to both systems: observations, station normals, ACF, background-error fields and climatology all come from one Fortran run, so the maps isolate the analysis engines. The Fortran namelist is the operational one (rejpre = 24, rejxvl = 20 — it rejects almost nothing) and the Python pre-filter is matched at the same thresholds, so both sides are effectively unscreened. Fortran QC enabled  |  Python QC disabled The EDC archive Fortran run with its own cross-validation screening active (rejpre = 8, rejxvl = 7), against Python fed every real gauge with no screening at all. Fortran QC enabled  |  Python QC enabled The EDC archive Fortran run against Python with the station-QC class enabled (boundary, range, climatology and cross-validation checks, th = 7): each station is hidden, predicted from its neighbours, and rejected when it disagrees by more than 7 × the expected error — iteratively, worst station first, with a second chance against the validated gauges.
